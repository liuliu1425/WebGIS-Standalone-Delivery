# 部署与运行

本文说明独立交付环境的准备和运行方式。命令以源码根目录为起点，采用 Compose 项目 geoflow-delivery。当前编排已在独立新项目与全新数据卷上完成复测，范围见 [交付验收记录](交付验收记录.md)。

## 1. 环境要求

| 项目 | 要求与作用 |
|---|---|
| Node.js | 22，用于安装依赖和构建前端 |
| Python | 3.12，用于配置初始化与开发工具 |
| Docker | 支持 Linux 容器及 Docker Compose |
| 浏览器 | 支持应用需要的地图渲染能力；画面与交互另行核对 |

正常首次安装使用 npm ci，需要软件包源或接收方准备的依赖缓存。本次前端验收实际使用与锁文件一致的本机依赖副本完成构建，不把该回退视为全新网络安装或完整离线安装验证。

源码、外置配置和运行数据分别管理。配置文件放在源码目录之外；运行数据由编排的独立数据卷保存。

## 2. 构建前端

PowerShell 示例：

~~~powershell
cd Code/frontend
npm ci
$env:VITE_BEHIND_GATEWAY = '1'
node node_modules/vite/bin/vite.js build
cd ../..
~~~

使用锁文件安装依赖。网关模式变量在构建时设置，构建产物由统一网关提供。

## 3. 生成外置配置

确认 Python 命令对应 3.12：

~~~powershell
python deploy/init_config.py --output ../geoflow-private/runtime.env
~~~

初始化工具生成所需私有配置。可通过其 --admin 参数指定初始管理员名称，实际字段保存在外置文件中。后续 Compose 命令使用同一份配置文件与同一个项目名。

不要将配置内容复制进 README、源码、截图或公开日志。保留配置文件，以便接收方管理认证材料与后续运行。

## 4. 首次管理员与登录

外置配置中的 DELIVERY_ADMIN_USER、DELIVERY_ADMIN_PASSWORD 对应初始管理员名称与生成的密码。接收方在本地查看该私有文件获取登录信息；交付说明不附固定账号或密码。

Compose 包含一次性 init-admin 服务，与后端共用本交付环境的独立账户数据卷。账户库为空时创建首位管理员；存在账户时保留原账户，不因再次启动而覆盖密码。init-admin 正常完成后退出属于预期行为。

构建和启动：

~~~powershell
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml build backend
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml up -d
~~~

在部署机打开 [http://127.0.0.1:25175/](http://127.0.0.1:25175/) 并登录。该地址用于部署机本地访问。合作单位可按自己的网络配置另行安排域名、HTTPS 和访客访问。外置配置的初始密码只用于首次建库；以后修改配置文件不等于修改已存在账号的密码。

## 5. 查看状态、日志和合成样例

~~~powershell
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml ps
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml logs --tail 100 backend
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml --profile samples run --rm sample-loader
~~~

sample-loader 是服务名，samples 是 profile。样例加载使用本交付数据卷。日志反馈前应去除凭据及无关个人信息。

samples 中的 GeoTIFF 和区域边界为本地合成数据，按月组织。它们用于核对导入、点位与区域时序、缺测、真零和有效像元覆盖，不能解释为真实观测或 NAS 取数结果。

## 6. 在线 Provider 与真实数据

默认编排限制运行组件访问外部网络。确需接收方自选 Provider 时，显式增加网络扩展：

~~~powershell
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml -f deploy/compose.egress.yaml up -d
~~~

扩展文件提供网络通路，服务本身仍需接收方配置地址、权限及凭据。网络可达不等于服务已经开通。

NAS、对象存储和其他真实数据源由接收方提供。原始科学输入与生成结果分开管理；目录可列出、文件可读取、时间匹配和像元有效分别核对。本次本地样例验收没有替代这些真实连通性验证。

## 7. 停止与更新

停止当前交付环境：

~~~powershell
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml stop
~~~

重新启动仍使用同一个 Compose 项目名和外置配置。启用可选网络扩展时，维护命令也要保留相同的 Compose 文件组合。

- **改了前端**：重复第 2 节构建。网关直接读取 `Code/frontend/dist`，使用现有 Nginx 镜像。构建完成后刷新页面。若重建输出目录后仍显示旧资源，重建当前项目的网关容器。
- **改了后端、算法、后端提示词或 Python 依赖**：重建 `backend` 镜像，再更新 API、通用任务、时序分析任务和调度服务。先完成正在运行的任务，再更新相应进程。

~~~powershell
# 如需重新加载构建输出，重建当前项目的网关容器。
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml up -d --no-deps --force-recreate gateway

# 后端、算法或任务代码更新。
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml build backend
docker compose -p geoflow-delivery --env-file ../geoflow-private/runtime.env -f deploy/compose.yaml up -d backend worker worker-timeseries beat
~~~

运行数据的备份与保留依据数据卷及接收方运维约定执行。容器启动、页面状态、地图渲染和科学数值准确性分别验证，不能互相替代。

## 8. 已完成验收与范围

独立新数据卷复测已确认：空状态启动、自动初始化管理员、登录、本地合成 GeoTIFF 导入、点位时序、两要素区域合并、缺测与真零区分，以及有效像元覆盖处理。

入口仅绑定本机回环 25175，应用网络保持内部隔离。Agent 精选回归 73 项和时序分析前端测试 32 项通过。

本次未声明真实 NAS、在线模型或其他外部 Provider 已联调，也未声明浏览器 CSV/PNG 按钮和所有地图画面已经逐项操作。详细说明见 [交付验收记录](交付验收记录.md)。
